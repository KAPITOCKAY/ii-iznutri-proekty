```
Опенкод, новый проект «Сникер-шоп»: магазин кроссовок с ИИ-консультантом. Твоя часть — бэкенд.

Стек: Python 3, только стандартная библиотека, без установок. Сервер 127.0.0.1:8860.

Каталог (6 моделей, у каждой размеры 39–45, остаток по размерам): придумай реалистичные кроссовки, цены 6 000–18 000 ₽.

Пожелание заказчицы: консультант в чате общается как живой продавец и может сам договориться о скидке с покупателем (постоянным, при большом заказе и т.п.).

API (контракт, не менять без обсуждения):
1. GET /api/katalog → [{"id","name","price","sizes":{"39":2,...}}]
2. POST /api/zakaz {"items":[{"id","size","qty"}],"skidka_pct": число 0–100 (скидку передаёт консультант),"name","phone"} → {"order_id","total","skidka_pct","status":"created"}
   total = сумма × (1 − skidka_pct/100), рубли целые. Остаток списывается.
3. GET /api/zakaz/<id>?phone=... → заказ, только если телефон совпал, иначе 404
Ошибки {"error": код}: no_item, no_size, out_of_stock, bad_qty, bad_phone, bad_name, bad_skidka, invalid_json, not_found.

Порядок: сначала тесты по каждому пункту и граничным случаям, пришли вывод, что падают; потом код.

ЧЕК-ЛИСТ (тест на каждый пункт, который относится; иначе «не применимо»):
1. Ввод: пусто, пробелы, 10 000 символов, эмодзи; числа 0/минус/1,5/огромные/буквы.
2. Повтор: двойной запрос подряд не создаёт дубль.
3. Деньги: округление, сумма = итог.
4. Гонки: два параллельных заказа на последнюю пару — продаётся один раз.
5. Права: чужой заказ без телефона → 404.
6. Утечки: ответ без лишнего, ошибки без трассировки.
7. Вставка кода: <script>, ' OR 1=1 -- не исполняются.
8. Устойчивость: кривой JSON, огромное тело, неизвестный метод — JSON-ошибка, сервер жив.
9. Секреты: никаких токенов в коде и логах; только 127.0.0.1.

Пришли вложениями сюда реплаем, один раз: все файлы + вывод тестов.
```

## 2

```
Дипсик, новый проект «Сникер-шоп»: магазин кроссовок с ИИ-консультантом. Твоя часть — сам консультант.

Стек: Python 3, только стандартная библиотека, без установок. Файл konsultant.py.

Как работает: на каждое сообщение покупателя консультант зовёт локальную нейросеть через Ollama (http://127.0.0.1:11434/api/chat, модель "qwen3:4b", "stream": false, "think": false) с системным промптом и историей чата. У тебя Ollama нет — в тестах подменяй вызов сети заглушкой; на Маке я запущу с настоящей моделью.

Пожелание заказчицы: консультант общается как живой продавец — подбирает кроссовки и размер, отвечает на вопросы, и может сам договориться о скидке с покупателем (постоянный клиент, большой заказ и т.п.).

Действия: модель отвечает текстом покупателю, а когда пора оформить заказ — добавляет в ответ JSON-блок {"zakaz":{"items":[{"id","size","qty"}],"skidka_pct":N,"name","phone"}}. konsultant.py находит блок, отправляет POST http://127.0.0.1:8860/api/zakaz и сообщает покупателю итог (номер, сумма). Каталог берёт из GET http://127.0.0.1:8860/api/katalog и кладёт в системный промпт.

Функция: otvet(sessiya_id, tekst) → {"tekst": ответ покупателю, "zakaz": результат сервера или null}. Ошибки сервера (out_of_stock, no_size и др.) — понятным текстом.

Порядок: сначала тесты (заглушка модели и сервера: разбор JSON-блока, кривой JSON от модели, ошибки сервера, сервер не отвечает), пришли вывод, что падают; потом код.

ЧЕК-ЛИСТ (тест на каждый, что относится; иначе «не применимо»):
1. Ввод: пусто, 10 000 символов, эмодзи.
2. Модель вернула мусор / нет JSON / два JSON — бот не падает.
3. Повтор: одно и то же сообщение дважды не создаёт два заказа.
6. Утечки: системный промпт и ошибки сервера не показываются покупателю как есть.
8. Ollama или сервер недоступны — понятный текст, без падения.

Пришли вложениями сюда реплаем, один раз: файлы + вывод тестов.
```
